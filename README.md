# 港中深校园动保 · 日常执勤记录

微信原生小程序 + 云开发。未填写云环境 ID 时走本地库（`apa_duty_live_v1`，会从旧的 `apa_duty_mock_v7` 迁过来），不会因为改存储键把已填记录丢掉。

AppID：`wx8ac912dded26ff5e`。工程根是含 `project.config.json` 的这一层，不要把开发者工具 `--project` 指到 `miniprogram\`。

公开脱敏源码：[GitHub 仓库](https://github.com/Godheritage/cuhksz-apa-miniapp)；反馈和代码修改可在仓库提 Issue / PR。不要把群聊、姓名、地址、密码或猫只实时动态贴进公开 Issue。

## 给同学用：底部四栏

- **每日执勤**：与组织点位档案共用同一批点位，点位卡可直接打开原档案。默认开启豪宅、祥波、TA；管理员在「管理 → 点位与每日执勤」可逐点开关，关闭后旧打卡仍可查。每个点位每天有早、午、晚、凌晨四班；成员可提前报名，同班可多人，所有已审核成员都能看到计划名单，报名不算打卡。到现场再打卡，可记投喂、添水、说明和最多 3 张照片；打卡后自己的报名自动撤下。具体时段按协会排班，系统保留实际提交时间，迟到仍可补记。
- **任务**：只放固定执勤以外的事项。已审核成员都可发布，普通成员发布的任务会标记来源；发布者可以自己领，也可等别人领。若发布时已经做完，在最后一栏填写完成情况并可附照片，直接进入管理员待审核；未完成就留空。其他待做任务仍按“领取 → 做完写结果并提交”操作。超过截止时间仍能交，页面会标“已超时”，管理员审核时也能看到。筛选器可看自己发布或做过的任务。普通成员只能删自己发布的任务，管理员可删任何任务。
- **组织任务日历**：在任务列表下方，按审核通过日期显示每天完成的任务项数；点日期看任务明细。发布或领取不算完成，同一任务同日多人完成仍算 1 项。
- **机动投喂**：底部中间打开日历，按日期记偶尔出现的猫是否见到、投喂或添水；现场备注可拍照或选图，最多 3 张。
- **我的**：随时看使用指南和轻量的自愿捐款入口；点开「更多功能」后才会出现点位、猫档和物资捐助登记。管理员还会看到标着「仅管理员可见」的管理入口，在那里审核任务。

捐款页只展示用户提供的微信收款码，付款前须核对页面标出的收款方；小程序不会自动扣款或判断是否到账。

管理员有待审核成员时，任务首页显示人数和直达审批入口，「我的」图标同时显示数量提醒；普通成员看不到。

机动投喂不预设每天出现，也不限某一只猫：在日历选日期，直接填新猫名，记录后自动成为筛选项。豪宅是旧表中的“寄养基地”，点位 ID 保持不变。

## 功能与权限

1. 管理员新增/删除执勤点（点上还有猫时不能删）。
2. 每点固定资产（食盆、喂食机、药箱等），占用与笼子分开。
3. 猫可以不挂点、不占用笼子/资产。
4. 健康猫按点位记录日常补粮和添水；有特殊情况的猫仍可在猫档单独记喂食喂水。点位记录不等于确认每只猫吃到。
5. 今日任务按地点分条；已审核成员可发布任务，成员回传描述/图片/名字，管理员审核，未通过重新上架。
6. 保密点：成员申请 → 管理员通过 → 当天有效动态密码才能看地址。管理员不回看密码。
7. 就医标记会释放笼子/资产；限时特护方案带教程，到期不再刷任务。
8. 财务台账 UTF-8 CSV（表头：`日期,收支,金额,科目,备注,经手人`）；捐助分电子/实体；实体可发搬运任务。
9. 深圳猫网绝育指标准备：官方链接、剪贴板资料包、认领状态。不代填、不抢号。
10. 「任务」页直接打开发布表单，默认单次，也可每日或每周指定星期；可设多人和人数上限。筛选器可看「我发布的」「我做过的」。多人任务默认最多 50 人，可自行填写上限。参与者互相可见，第一条回传审核通过后本次任务完成，不再领取或提交；此前已提交的回传仍可审核，历史记录保留。
11. 管理员专用工作记录：按日期记录内容与 PF，不排名。9.22 表格内 9 月 16–22 日的历史工作记录已导入；更早没有可靠来源，不补造。原表没有的 PF 不会代填。
12. 管理员专用长期资料：领养提醒、教程、密码备忘。列表不返回密码正文，打开单条时仍默认隐藏。
13. 「我的」里随时打开使用指南。页面每次打开都刷新身份，分别显示简短的成员或管理员用法。
14. 猫档可显示附群消息来源的最近动态，未确认身份的新猫保留“待核对”标记。管理页提示在校猫缺点位、缺照片数量，交由熟悉现场的管理员核实。
15. 底部保留「每日执勤」「任务」「机动投喂」「我的」四栏；其余功能默认收在「我的 → 更多功能」。机动投喂用月历记出现、未见到和投喂日，不自动生成每日任务。

身份：`guest` / `pending` / `member` / `admin`。前端藏按钮不够，读写都走云函数 `api`，按 `users.role` 校验。

## 用官方 CLI 打开（不要手点编译）

文档：[命令行 V2](https://developers.weixin.qq.com/miniprogram/dev/devtools/cli.html)、[HTTP V2](https://developers.weixin.qq.com/miniprogram/dev/devtools/http.html)、[Automator](https://developers.weixin.qq.com/miniprogram/dev/devtools/auto/quick-start.html)。

先在开发者工具 **设置 → 安全设置** 打开**服务端口**。`--port` 是 HTTP 服务端口（`%LOCALAPPDATA%\微信开发者工具\User Data\<MD5>\Default\.ide`），`--auto-port` 是 automator WebSocket，不要混用。

```bat
"C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat" --lang zh islogin --port <服务端口>
"C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat" --lang zh open --project "F:\works\港中深相关事务\动保" --port <服务端口>
"C:\Program Files (x86)\Tencent\微信web开发者工具\cli.bat" --lang zh auto --project "F:\works\港中深相关事务\动保" --auto-port 9420 --port <服务端口>
```

`open --project` 每次执行都会自动编译刷新并打开模拟器。`miniprogram-ci` 只适合出预览码，不能代替看模拟器。

## 无人值守质量 loop

开发者工具保持打开且已登录、服务端口已开之后，在工程根执行：

```bat
node scripts/quality-loop.js
```

或 `powershell -File scripts/devtool-iterate.ps1`。

每轮会：探测 HTTP 服务端口 → `GET /v2/islogin` + `/v2/open` 编译刷新 → 跑 `selfcheck.js` 与 `static-quality.js` → 尝试截模拟器 → 写 `debug-shots/round-*/notes.md`。

不要手点编译。改完再跑同一条命令。

说明：官方 `cli.bat` 在本机仍误报「服务端口已关闭」，所以编译走 HTTP，不走 cli。Cursor 代理进程没有桌面截屏权限（PrintWindow/GDI/PIL 都是白/黑/失败），看界面用你发的模拟器图 + 源码/自检。若以后要 automator 截图，需开发者工具自己把 CLI 能力认出（设置页端口号不要显示成非法的 179600）。

本机 PATH 没有 `wechatide` 时不要假装有官方 MCP。安装目录若有 `wechatide.cmd`，须先 `wechatide auth -c Cursor`。

## 云环境

1. 把 `miniprogram/config.js` 的 `cloudEnvId` 填成环境 ID。
2. 按 `database/rules.json` 配置集合权限；固定执勤使用 `routine_duty_checkins`，机动投喂使用 `mobile_feed_logs`。业务数据由云函数读写，客户端不可直接读写数据库。
3. 上传 `login` / `api` / `seed`（云端安装依赖）。
4. 「我的」→「写入种子数据 / 成为首位管理员」。

## 三种人

- **游客 / 待审核 / 已拒绝**：身份页。看不到内部点位、猫档、任务、财务、捐助、绝育指标和保密地址。
- **普通成员**：做任务并回传、点位与猫档、记进食进水、申请保密地址、登记捐助、复制深圳猫网资料包。
- **管理员**：以上全部 + 审成员、维护点位/资产、批地址申请、就医/特护、台账 CSV、捐助搬运、绝育说明。
